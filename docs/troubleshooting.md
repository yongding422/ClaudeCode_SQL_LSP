# Troubleshooting

- A terminal showing no output is normal: the server expects framed LSP input. Use the integration suite to exercise it.
- If a client reports unframed stdout, launch the compiled/published DLL directly, never `dotnet run` or a wrapper that prints status to stdout.
- Invalid initialization options report JSON Schema paths through an error `window/showMessage` and stderr, with analysis capabilities disabled. Correct the options and restart. This avoids a verified OmniSharp initialize-callback exception path that leaves clients waiting for a response.
- Workspace file edits refresh after watcher debounce. If native watching is unavailable, send watched-file notifications, re-open files, or restart. Open buffers continue to win over disk changes. Excluded directories, links, oversized files and statements damaged by syntax errors may have no outlines.
- Empty definition/reference results can mean unresolved, ambiguous or unsupported targets. Check schema/database qualification and `resolution` options. Each workspace root is a separate project; source context, duplicate declarations and case rules can prevent a jump. Dynamic SQL and numbered/remote targets are not bound.
- `dotnet --info` on the development host failed in the SDK workload installer; `dotnet --version`, restore, build, test and publish work. The language server has no workload dependencies.
- `--stdio` is the only transport argument. Invalid command-line arguments print usage to stderr and exit with code 2.
- Online profile status arrives via `window/logMessage` on navigation/search: `missing-secret` means the server process did not inherit the configured environment variable; `profile-endpoint-mismatch` means its server/database differ from the approved profile; `tls-required` rejects disabled encryption. No connection string or provider error text is logged. Restart after fixing initialization settings.
- `Partial` metadata can mean hidden/encrypted source, limits, or dependency permission denial. Check the coverage codes and [permissions guide](online.md). A metadata-only definition is a comment description, not recoverable original DDL. Unavailable profiles return no expired catalog navigation results; offline mode never tries them.
- Live tests require Docker with Linux x86-64 containers and enough free memory for a 2 GiB SQL Server container. They accept the Developer image EULA for an isolated fixture, bind only loopback, and clean up their own container. The Docker fixture name starts with `sql-lsp-test-` and has label `sqlscriptdom-lsp.fixture=true`; no other containers are modified. Force-killing a test process may leave its fixture behind.
- Hybrid mappings must use file directory URIs for existing initialized workspace roots and name only enabled profiles. An unregistered, duplicated, invalid or link root fails configuration validation. A mapping's default profile must belong to its profile list. Unmapped roots cannot navigate other roots' local definitions or catalog targets.
- A Different comparison in workspace symbol data means module tokens differ. Whitespace/comments and CREATE/ALTER headers are ignored; semantic behavior is not inferred. Unavailable covers missing visible/original source or a failed profile; Ambiguous covers duplicate declarations/competing identities. Source preference does not fix ambiguity. See [hybrid setup](hybrid.md).
