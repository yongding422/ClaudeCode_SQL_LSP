# Security and resource model

The default server is an offline stdio process. It listens on no network port, exposes no SQL execution/deployment method and does not run analyzed scripts. The local LSP client and account are trusted: JSON-RPC input and open buffer text can consume memory, and this is not a sandbox against a hostile same-user client. `maxFileSizeBytes` bounds analysis/disk reads, but an excluded open buffer retains text so subsequent incremental edits can recover; there is no process-wide buffer count or memory quota.

Workspace disk reads are confined to initialized roots, exclude standard build/dependency paths and reject file/directory links, reparse points and roots beneath linked ancestors. Paths/URIs are normalized by platform APIs. Root/child link checks are tested with Windows junctions and Unix symlinks. Checks are best-effort against ordinary links, not atomic protection against a same-user attacker swapping filesystem entries during a read. Explicit client-opened buffers may be outside scanned roots and have their own context.

ScriptDOM parsing is limited to at most four active parses per process (fewer when the CPU count is lower). Queued jobs are cancellable; superseded results cannot publish. Disk refreshes remove completed job bookkeeping, deleted snapshots are released, and reads pool small buffers instead of allocating the maximum file size for every small file. Metadata acquisitions are serialized per profile, bounded to two mapped profiles concurrently, and retain the documented per-object, aggregate and timeout limits. Indexes remain in memory; large workspaces can still take seconds to initialize.

Database access is explicitly enabled, environment-secret-only and limited to configured endpoints/databases. The provider requires TLS, parameterizes filters and sends fixed SELECT metadata queries. `ApplicationIntent=ReadOnly` is routing intent; database permissions enforce authorization. AttachDBFilename, User Instance and Failover Partner are rejected before connection because they can attach files or route outside the approved endpoint. SQL authentication is tested; other authentication environments require separate verification. No administrator credentials belong in plugin configuration. Follow `online.md` for least privilege and freshness/retention limits.

Provider failures expose fixed safe codes. Unexpected workspace initialization exceptions expose one generic failure message, disable capabilities/analysis and still answer the handshake. Parser/workspace operational failures suppress SQL and exception details. Wire/process tests inject secret sentinels through child-only environment variables and assert their absence from notifications and stderr. Syntax diagnostics necessarily contain relevant SQL tokens; they are requested analysis output, not secret-redacted operational logs. Symbols/drift output can expose object names by design.

Catalog source files use private ACLs/modes and advisory read-only flags with bounded generations and normal-shutdown removal. Force termination can leave private snapshots; the server does not delete arbitrary temp directories during startup. See `online.md` for cleanup. Claude's raw debug/session logs can contain analyzed SQL and machine paths. The smoke uses public fixtures only and stores logs locally under ignored artifacts; inspect and redact before sharing. No secrets, signed-in auth output or private SQL are committed as evidence.

Packages bundle .NET 10.0.13, NuGet dependency inventory and supplied third-party notices. SDK and dependency graphs are pinned. Run the NuGet vulnerability audit again when rebuilding/releasing; a clean audit is a feed-based check, not proof against unknown defects. CI packaging produces reviewable artifacts and does not publish/install them automatically.
