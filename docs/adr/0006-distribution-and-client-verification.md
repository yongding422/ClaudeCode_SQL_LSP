# ADR 0006: M5 distribution, client evidence and resource bounds

Date: 2026-10-11. Status: accepted.

The official [plugin reference](https://code.claude.com/docs/en/plugins-reference) and [code intelligence documentation](https://code.claude.com/docs/en/plugins/code-intelligence) were rechecked against installed Claude Code 2.1.201. Keep the minimal root `.lsp.json` configuration with separate command/args, stdio and `.sql` to `sql`. Avoid newer timeout/restart fields whose acceptance is version-dependent. Strict validation checks manifests; actual discovery/launch/requests are a distinct gate. CLI sessions load the local plugin with `--plugin-dir`; no global install or update is required.

The installed Windows client intermittently rejected PATH lookup of `dotnet`. Use RID-specific multi-file self-contained apphosts with `${CLAUDE_PLUGIN_ROOT}` in the command, rather than a wrapper that can mix build/text output with protocol bytes. Pin runtime 10.0.12 (SDK 10.0.401), verified on [NuGet](https://www.nuget.org/packages/Microsoft.NETCore.App.Runtime.win-x64/10.0.12). Declare win-x64/linux-x64/osx-arm64 restore graphs and lock them. Reflection-heavy dependencies remain untrimmed, without AOT/single-file deployment. Include dependency/license metadata, deterministic ZIP ordering/timestamps and build provenance. Native platform tests gate artifacts in CI; local Windows evidence does not establish macOS/Linux host success.

An isolated, public SQL-only Claude fixture proved automatic syntax diagnostics through real initialize/didOpen/publishDiagnostics/shutdown traffic. The installed client's LSP navigation tool was not exposed in the constrained sessions, including a child-only ENABLE_LSP_TOOL compatibility probe. Record this limitation rather than attributing generic client navigation to Claude. The compatibility flag is not required package configuration or a claimed official interface. See `claude-verification.md` for evidence and reproduction.

Hardening bounds active parses to four, removes completed disk jobs, pools bounded reads, rejects linked ancestors and unsafe SQL connection attachment/failover settings, and handles unexpected initialization failures without sensitive exception messages or a hanging handshake. Regression tests cover file churn, rapid edits, concurrent requests, workspace isolation, child-environment secrets, UTF-8 reads, links, unknown methods and apphost startup without dotnet discovery. Performance targets are measured with real stdio traffic and reported with workload/hardware/contention rather than enforced as unreliable wall-clock test assertions.

The native package CI uses `macos-15` for osx-arm64. GitHub's [runner inventory](https://github.com/actions/runner-images) confirms that standard label is ARM64; macOS 14 is being retired. Test fixtures resolve the system temp directory's physical path before passing workspace roots so macOS's /var alias does not conflict with strict linked-ancestor rejection.
