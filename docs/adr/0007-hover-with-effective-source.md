# ADR 0007: M6 hover with verified source selection

Date: 2026-10-13. Status: accepted. Scope: first M6 increment, not completion of the optional M6 backlog.

Implement `textDocument/hover` against the existing immutable navigation snapshot. [LSP 3.17 hover source](https://github.com/microsoft/language-server-protocol/blob/gh-pages/_specifications/lsp/3.17/language/hover.md) specifies Hover/null, optional document range, content preferences and hoverProvider. The compiled OmniSharp **1.0.0** API verifies `IHoverHandler`, `HoverParams`, `HoverRegistrationOptions`, `MarkedStringsOrMarkupContent`, `MarkupContent` and `MarkupKind`. Its [upstream feature source](https://github.com/OmniSharp/csharp-language-server-protocol/blob/master/src/Protocol/Features/Document/HoverFeature.cs) is a reference, not a substitute for compiling the pinned API. Hover needs no new library; verification also requires the security pin updates recorded below.

`SqlNavigationIndex.Hover` reuses Definition's selected target rather than independently choosing a candidate. Return the requesting reference's span, with kind/metadata from the selected definition. Direct declaration anchors remain inspectable. Attach plain bounded documentation to declarations and lexical type descriptions to locals. Use actual ScriptDOM type nodes, not string-based DDL reconstruction; default values/body expressions are excluded. Catalog documentation uses catalog-authoritative identities and visible metadata, preserves incomplete coverage and capture time, and never borrows local syntax into a database-selected result. Hybrid comparison lookup must include the requesting source context to avoid cross-workspace comparison leaks.

Plaintext is the fallback format. Client-preferred Markdown is safely fenced text; dynamic fence length and display-only control sanitization prevent identifier markup injection. Identity comparison remains unchanged. Preview/member/content bounds restrict response size while leaving the full index intact. Workspace syntax and catalog observations remain explicitly distinct; column binding, projection inference, migration evaluation and runtime semantics are not claimed.

Tests cover UTF-16/CRLF/emoji and escaped identifiers, signature/body omission, lexical types, alias/column boundaries, missing/ambiguous/unsupported bindings, source preference and comparison context, cancellation, invalid initialization, incremental edits/close, content negotiation/injection and response bounds. Deterministic catalog fixtures cover rename/hidden source, type arguments/alias types and limits; disposable SQL Server tests cover real metadata/restricted accounts and existing hybrid/outage fixtures exercise hover. The plugin manifest stays minimal after rechecking the [official reference](https://code.claude.com/docs/en/plugins-reference); advertised server hover and Claude's tool exposure remain separate evidence.

The Oct 13 NuGet audit newly reported high/moderate PKCS advisories [GHSA-846f-f764-76mx](https://github.com/advisories/GHSA-846f-f764-76mx) and [GHSA-2fmv-rv2c-59x7](https://github.com/advisories/GHSA-2fmv-rv2c-59x7). Add an explicit centrally pinned **System.Security.Cryptography.Pkcs 9.0.21** reference to the SqlServer provider to override SqlClient's affected 9.0.18 transitive selection. Re-evaluate and lock the graphs, test SqlClient compatibility, and bundle the available **.NET 10.0.13** runtime in all self-contained RIDs. SDK 10.0.401 and language/parser/test package pins remain unchanged. Rebuild distributions and re-run the audit; previous M5 audit results remain historical Oct 11 evidence, not a current security claim.
