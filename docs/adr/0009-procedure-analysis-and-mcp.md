# ADR 0009: shared procedure analysis and read-only MCP delivery

Date: 2026-10-14. Decision: implement the first two increments of the [procedure-understanding plan](../procedure-understanding-implementation-plan.md). General M6 editor enhancements remain deferred.

The standard LSP call hierarchy remains a call graph. Table effects and unified coverage use a separate typed core report, not fake call edges. `SqlNavigationIndex.AnalyzeProcedure` and the ScriptDOM effect visitor share the existing scoped reference resolver. Each module reports its own direct effects; bounded procedure/function/view expansion retains separate module identities, revisions and issue lists.

Verified dependencies: .NET SDK 10.0.401, self-contained runtime 10.0.13, ScriptDOM 180.117.0 and OmniSharp 1.0.0 remain pinned. Add [official C# MCP SDK 2.2.0](https://www.nuget.org/packages/ModelContextProtocol/2.2.0) and Microsoft.Extensions.Hosting 10.0.13, with checked-in lock files. The SDK's net10.0 target and stdio hosting API were verified against its [tagged sample](https://github.com/modelcontextprotocol/csharp-sdk/blob/v2.2.0/samples/QuickstartWeatherServer/Program.cs) and by compiling a real adapter. Its installed `CallToolResult.StructuredContent` is `JsonElement?`; do not substitute APIs from another SDK version.

Compiled reflection/API checks against the installed ScriptDOM confirmed DML `Target`, MERGE `ActionClauses`, SELECT `Into`, OUTPUT `IntoTable`, table-variable declarations and the generic fragment visitor. Golden tests check actual operation identities and source ranges. SELECT INTO temp declarations and TRUNCATE references extend the same semantic extractor rather than introducing a second name binder.

`SqlLsp.Mcp` publishes two read-only tools, `find_procedures` and `analyze_procedure`, using actual newline-delimited MCP JSON-RPC. It reuses `ServerState.InitializeSourcesAsync` for validated source acquisition and offline/online/hybrid resolution. LSP and MCP are separate processes with independent snapshots: MCP reports saved files/catalog captures and does not claim access to unsaved buffers. The initial adapter is lazy, so protocol initialization does not wait for a repository scan. A canceled initialization disposes incomplete state before retry.

Configuration defaults to offline. An explicitly provided `--config` or `SQLLSP_MCP_CONFIG` file uses the existing schema and opt-in profile rules; it is not automatically discovered in a repository. No arbitrary SQL execution tool exists. Metadata acquisition still uses fixed read-only queries. Detailed configuration/IO errors are suppressed; neither logging nor aggregate metrics include analyzed module bodies.

[Claude plugins support bundled MCP servers](https://code.claude.com/docs/en/mcp#plugin-provided-mcp-servers) and [plugin skills](https://code.claude.com/docs/en/skills). Packages include separate self-contained LSP and MCP directories to avoid conflicting runtime dependency versions, plus `skills/explain-procedure/SKILL.md`. This preserves one marketplace installation. Native CI checks both apphosts, Unix modes and both protocols. No hooks are installed.

The external paired evaluation runner measures client behavior, not just server requests. It freezes model/effort, randomizes arm order, copies SQL-only fixtures into fresh sessions, retains errors/timeouts and leaves accuracy scoring to reviewers. Raw transcripts and answers require explicit local retention flags. A small public fixture validates mechanics; it cannot establish superiority over Grep/Read. Opt-in server telemetry, control-flow/value tracing and indexing optimizations remain subsequent increments.
