# ADR 0014: versioned materialized discovery snapshots

Status: accepted and implemented behind opt-in `indexCache`; validation is tracked by R3b. No general performance claim.

The report cache cannot serve discovery before the workspace is parsed. Rich analysis needs real ScriptDOM ASTs, while discovery needs immutable extracted facts. Introduce a separate discovery/query interface; never deserialize ASTs or manufacture empty syntax trees to satisfy `DocumentSnapshot`.

Choose bounded versioned JSON snapshots for the first offline implementation. Existing .NET JSON, hashing and atomic-file primitives compile in all shipped targets and add no dependency. SQLite would add a provider/native deployment matrix without a demonstrated need for concurrent updates or SQL queries: immutable generations and one nonblocking writer lease meet this workload. Revisit SQLite only after measurements show JSON restore/query/storage is the bottleneck. The compiling spike is a roundtrip of real extracted declaration/reference/diagnostic DTOs with no AST types; exact locations/facts must equal a fresh parse.

Opt-in `indexCache` is independent from report-cache and metrics settings and disabled in existing starters. A snapshot stores bounded per-file physical URI, raw-content hash, decoding, source revision, context/rules, declarations, static references/local bindings and diagnostics. Source facts contain private SQL-derived identifiers/snippets; protect them with the same private permissions/link checks as report storage. No online catalog is silently persisted through this path.

Before serving, enumerate current inputs and read/hash their bytes, including same-size/same-time edits. Snapshot identity includes root, parser assembly/options, resolver/DTO version, source configuration, project membership/comparison evidence and inventory. Reuse facts only for matching content and context/config; additions/deletions change the complete candidate set. Rebuild changed/invalid entries, then atomically publish an immutable generation. A read-only/unavailable/corrupt/incompatible cache falls back to fresh extraction, with status and all validation cost visible.

Discovery consumes only materialized facts. Analysis parses the selected file and bounded reachable static dependencies on demand while retaining all verified materialized symbols for resolution/ambiguity. Missing rich bodies stay explicit and never become known-empty effects. Reports against a partial parsed subset must not reuse a cache fingerprint that omits the complete discovery candidate set. Analyze depth/module limits remain explicit. Multiple readers can use immutable snapshots; writers coordinate retention/atomic replacement and never block analysis on cache contention. Bound entry size, file count and aggregate bytes and prune only owned names inside the validated cache root.

Required tests include DTO roundtrip and source-parity, real MCP restart with zero discovery parses, selected-body parsing, same-size/time edits, added competing declarations, deleted/renamed sources, config/parser changes, corruption, path links/permissions, cancellation and concurrent writers. R6 labels fresh empty, persisted restart and live-process groups separately; no warm/cold relabeling. The reference corpus exceeded the initial 32-MiB plain JSON limit. Store lossless GZip-compressed JSON using built-in .NET support, bounding encoded input at 32 MiB and decompressed JSON at 128 MiB; keep the 128-MiB aggregate disk limit. The first over-limit probes are retained as unsuccessful persistence evidence, not relabeled cache hits.
