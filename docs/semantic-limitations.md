# Current limits

- The 0.7.0 read-only MCP adapter exposes table operation footprints, source revisions, bounded callee/view expansion and visible coverage issues. It analyzes saved workspace/catalog snapshots independently from LSP unsaved buffers. CTE/view writes, dynamic SQL, implicit/runtime effects and opaque relation sources remain partial. Control-flow/transaction/value tracing are source interpretation, not deterministic analyzer features. See [procedure analysis](procedure-analysis.md).

- M6's first increment adds hover to syntax diagnostics, outlines, conservative definition/references, workspace/catalog search and mapped hybrid definition comparison. ScriptDOM is not a semantic SQL binder; missing tables and invalid column names do not produce semantic diagnostics.
- Hover shows declared syntax for workspace/unsaved definitions and permitted metadata for selected catalog objects. Defaults/body expressions, projected column types, migration effects and implicit nullability are not inferred. Qualified relation aliases describe their verified relation; the column token itself has no fabricated type hover. Catalog limits/permissions remain explicit, and encrypted source does not acquire invented DDL. Content is plaintext or safely fenced Markdown; member previews and display strings are bounded. Direct declaration hover inspects that anchor, while reference hover follows effective-source selection. Claude hover availability requires separate client evidence; generic LSP tests are authoritative for implemented behavior.
- Static coverage includes EXEC procedure names, named table/view uses, table-only ALTER/DROP uses, schema-qualified scalar functions and table-valued functions. Verified alias qualifiers navigate to their relation; column declaration binding and projection lineage are not implemented. Derived-table qualifiers navigate to their local alias. Some complex DML/MERGE, XML/JSON/pivot table-source aliases and CLR method binding remain unsupported.
- Offline object resolution is limited to the same workspace root and database context. `USE`, explicit name parts and configured defaults establish database context; cross-server names require future mapping. Offline comparison is explicit ordinal matching. Without configured schema, multiple matching declarations are ambiguous. Distinct migration files declaring the same identity remain ambiguous, including CREATE/ALTER pairs. Online matching uses the selected catalog's LCID and case/accent/kana/width/binary flags through SqlString, or an explicit ordinal override. This is not a complete SQL Server binder or a guarantee for every collation version/linguistic edge case. Default schema is retrieved for the metadata account, with dbo fallback; specify a schema when analyzing a different user's SQL.
- CTEs, temporary tables, scalar/table variables and module parameters have conservative lexical scopes. Temporary tables are scoped to the batch/module; cross-batch/session/global-temp lifetimes, control-flow existence and dynamically created objects are not inferred. Duplicate/forward local names do not fall back to global definitions. Dynamic/variable/remote/numbered EXEC targets are unsupported; named parameter labels are excluded from caller variable references.
- ALTER TABLE outlines identify the affected table; they do not imply a new table definition. Views map to LSP Interface and tables to Class because LSP has no SQL-specific kinds. Dynamic SQL is parsed as syntax, with no fabricated semantic target.
- Malformed statements may have no declaration; safely parsed declarations in other batches are retained. Parser diagnostics use the token span at the reported offset, or a point at EOF.
- UTF-16 is the only supported position encoding. Parsing cancellation is cooperative at tokenization and processing boundaries; ScriptDOM's internal AST parser has no CancellationToken API. Results are still discarded immediately if obsolete.
- File/directory create/change/delete/rename events refresh the index after debounce; clients can also send watched-file notifications. Watcher overflow triggers reconciliation. Native watcher resource/permission failures are logged; client notifications and re-open refresh remain available. Snapshot indexing is in memory and reference queries scan indexed static uses; M5 measures synthetic 1,000/10,000-file workloads, not all query shapes or large hybrid projects. See `performance.md`.
- Multi-root initialization keeps independent project contexts. Runtime workspace-folder/configuration changes and full user-defined include/exclude glob configuration are not yet implemented.
- Online mode discovers SQL tables/views/procedures/functions and their visible columns, parameters and definitions. Triggers, synonyms, CLR objects and richer type/column binding are later work. Catalog visibility depends on permissions; zero rows cannot prove the database has no objects. Hidden/encrypted or oversized modules have no fabricated source. Metadata-only file snapshots explicitly describe their limits. Reference locations come from parsed visible modules/open buffers, not invented spans for catalog dependencies; dynamic/caller-dependent/cross-server dependency coverage remains incomplete.
- Online selects one enabled profile, requiring defaultDatabaseProfile when several are enabled. Other profiles are not contacted. Online repository scanning is off unless scanInOnline is true. This explicit option retains ambiguous candidates; hybrid precedence applies only in hybrid mode. Hybrid uses explicit initialized-root mappings, with profile/database/schema/kind identity filters and duplicate/ambiguity guards. Unmapped roots stay offline; cross-server names remain unsupported. Runtime mapping/profile reconfiguration is not implemented. No SQL execution/deployment API exists.
- Hybrid lexical comparison uses the mapped default profile, or explicit offline rules when no default is available. Full rebinding across USE changes with different collations is not implemented. Select a default profile and qualify names for a predictable execution context. Different profile identities are not merged by short name, even when they point to similar databases.
- Drift compares safely parsed procedure/view/function declaration tokens. It ignores whitespace/comments, CREATE/ALTER acquisition headers and the declaration's own name; string values, numeric values and body identifier spellings remain significant. Different means normalized text differs, not proven behavioral drift. Case/linguistic equivalence and optional syntax differences may still appear as text differences. Original table DDL, encrypted/hidden/oversized module source and ambiguous counterparts cannot be compared and remain Unavailable/Ambiguous.
- Database refresh is demand-driven on navigation/search after TTL. Cached permissions/data can persist until TTL or restart; expired data is not used after failed refresh. Limits or denied dependency access produce partial status. Module parsing still uses the configured ScriptDOM version, not an inferred parser version from server version. Read-only snapshots are private files with advisory filesystem write restrictions, not an editor-specific virtual scheme; abrupt process termination can leave private files for manual cleanup.
- Hybrid refresh gathers mapped profiles with two concurrent acquisitions and a shared 30-second load/materialization budget. It can delay the requesting navigation while a profile times out; local diagnostics/outlines continue independently. Per-profile failures do not discard healthy snapshots. Expired definitions are excluded after failure; the last verified comparison/default-schema rules can still be used to resolve local sources. Stale definition fallback is disabled; allowStaleDatabaseCache=true is rejected.
- Self-contained win-x64/linux-x64/osx-arm64/osx-x64 packages passed native process/provider tests in [GitHub CI](https://github.com/yongding422/ClaudeCode_SQL_LSP/actions/runs/38500332165), including Apple Silicon and Intel Macs. Windows Claude Code 2.1.201 automatic SQL diagnostics and hover have actual client evidence; Claude model tool calls on Mac remain unverified. Other authentication modes, signed distribution and all-platform client certification remain unverified. See `claude-verification.md`, `installation.md`, `macos.md` and `security.md` for exact limits.
