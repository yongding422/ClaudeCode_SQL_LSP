# Offline architecture (M0–M2)

`SqlLsp.Server` hosts OmniSharp 1.0.0 for LSP 3.17 framing, lifecycle, request scheduling, capability registration and request cancellation. A shared `ServerState` validates initialization options against an embedded JSON Schema, sets up the offline source and converts plain core ranges/diagnostics into protocol types. Compiled handlers implement text synchronization, document symbols, definition, references, workspace symbols and client file notifications. The definition response may be a single Location or an array, both allowed by LSP.

`SqlLsp.Core` is independent of the LSP framework. `SqlParser` creates an actual ScriptDOM parser for the selected dialect for each parse. It retains source, tokens, AST (or an empty fallback when ScriptDOM returns null), syntax diagnostics and top-level declarations. A batch visitor extracts CREATE, ALTER and CREATE OR ALTER procedure/view/function declarations and CREATE/ALTER tables. It deliberately does not recurse into local table declarations inside procedure bodies. Errors intersecting a declaration cause that declaration to be omitted.

`SourceText` translates .NET UTF-16 offsets to zero-based positions and applies sequential edits, with full replacements supported. CRLF is one line break; LF and CR are also supported. Positions past a line's length clamp to its end. Negative/out-of-document ranges and edits splitting surrogate pairs are rejected atomically.

`WorkspaceFiles` acquires only bounded local `.sql` files, excludes common build folders and reparse points, and checks configured-root containment before reads. `DocumentStore` holds disk snapshots and open overlays, replaces the effective per-URI index atomically, cancels superseded jobs, and verifies overlay identity before publishing diagnostics. Reopen starts a new identity even if its version number resets. Symbol requests await the current parse using their own cancellation token; canceling a request does not close the buffer. Close removes the overlay, clears diagnostics, and refreshes the saved disk source.

`SqlSemanticExtractor` reads real AST nodes for static EXEC targets, named relations and selected functions. Local scopes distinguish modules, batches, CTE-bearing statements and nested queries. Alias collectors do not enter derived tables or predicate subqueries; correlated queries can use outer bindings. Named EXEC argument labels are not caller variable uses. Duplicate/forward local names, dynamic and remote targets are explicit unsupported results.

`SqlNavigationIndex` consumes one completed immutable document snapshot set per request. Identities retain project context, server/database/schema/name and object kind. Identifier parts come from the AST, without splitting decoded names on dots. Resolution records status, candidates and provenance; a unique verified candidate is required for navigation. Reference search compares declaration anchors and resolves each supported static use, retaining the same source context. This initial in-memory implementation scans references rather than persisting a reverse cache; large-workspace benchmarks are later work.

`WorkspaceWatcher` coalesces native file events with a 100 ms debounce. SQL file events refresh individual snapshots; directory renames/deletes and watcher overflow reconcile the source registry. Non-SQL file writes do not trigger whole-workspace parsing. Native watcher setup failure preserves client notifications/re-open refresh and logs a status to stderr. Disk jobs have independent cancellation and identity guards, so an older read cannot overwrite a newer file result or an open buffer. Query requests wait for the current pending jobs and support cancellation.

The same effective snapshot/index path remains ready for M3/M4 sources without protocol types in provider contracts. Four projects contain executable functionality; future provider assemblies will be introduced when implemented.
