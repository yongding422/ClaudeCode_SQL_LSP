# Architecture (M0–M6 hover increment)

`SqlNavigationIndex.AnalyzeProcedure` consumes the retained AST and the existing scope/resolution model. Statement context classifies direct relation operations; each expanded procedure/function/view retains its own identity, revision, facts and coverage issues. Cycles, depth/module limits and fact budgets bound output. `SqlLsp.Mcp` exposes discovery and analysis via the official C# SDK's stdio MCP transport, reusing `ServerState.InitializeSourcesAsync` and `NavigationAsync` for source acquisition. LSP/MCP have independent snapshots: the adapter receives saved files/catalogs, not unsaved LSP overlays. A packaged skill guides evidence collection and source interpretation without hooks. See [ADR 0009](adr/0009-procedure-analysis-and-mcp.md).

`SqlCallHierarchyHandler` registers the three standard call hierarchy methods through OmniSharp's compiled grouped handler. `SqlStaticReference.IsInvocation` separates actual EXEC/function/TVF invocations from alias navigation references. `SqlNavigationIndex` assigns calls to callable module ranges, resolves selected-source targets, groups sites, reports partial recognized-call coverage and validates prepared identity/ranges/source revisions against current immutable snapshots. No recursive traversal, SQL execution, hook or model call is embedded in the server. See [call hierarchy](call-hierarchy.md).

`SqlSymbolDocumentation` carries bounded, plain declaration documentation independently of LSP. ScriptDOM declaration/type nodes supply syntax signatures, while catalog materialization supplies authoritative observed metadata. `SqlNavigationIndex.Hover` reuses definition selection, source/lexical anchors and request-document ranges; hybrid comparisons are filtered by requesting context. `SqlHoverHandler` negotiates plaintext or safely fenced Markdown and registers only implemented hover support. Preview/formatting code does not change identity matching or execute SQL.

`SqlLsp.Server` hosts OmniSharp 1.0.0 for LSP 3.17 framing, lifecycle, request scheduling, capability registration and request cancellation. A shared `ServerState` validates initialization options against an embedded JSON Schema, sets up the offline source and converts plain core ranges/diagnostics into protocol types. Compiled handlers implement text synchronization, document symbols, definition, references, hover, workspace symbols and client file notifications. The definition response may be a single Location or an array, both allowed by LSP.

`SqlLsp.Core` is independent of the LSP framework. `SqlParser` creates an actual ScriptDOM parser for the selected dialect for each parse. It retains source, tokens, AST (or an empty fallback when ScriptDOM returns null), syntax diagnostics and top-level declarations. A batch visitor extracts CREATE, ALTER and CREATE OR ALTER procedure/view/function declarations and CREATE/ALTER tables. It deliberately does not recurse into local table declarations inside procedure bodies. Errors intersecting a declaration cause that declaration to be omitted.

`SourceText` translates .NET UTF-16 offsets to zero-based positions and applies sequential edits, with full replacements supported. CRLF is one line break; LF and CR are also supported. Positions past a line's length clamp to its end. Negative/out-of-document ranges and edits splitting surrogate pairs are rejected atomically.

`WorkspaceFiles` acquires only bounded local `.sql` files, excludes common build folders and reparse points, and checks configured-root containment before reads. `DocumentStore` holds disk snapshots and open overlays, replaces the effective per-URI index atomically, cancels superseded jobs, and verifies overlay identity before publishing diagnostics. Reopen starts a new identity even if its version number resets. Symbol requests await the current parse using their own cancellation token; canceling a request does not close the buffer. Close removes the overlay, clears diagnostics, and refreshes the saved disk source.

`SqlSemanticExtractor` reads real AST nodes for static EXEC targets, named relations and selected functions. Local scopes distinguish modules, batches, CTE-bearing statements and nested queries. Alias collectors do not enter derived tables or predicate subqueries; correlated queries can use outer bindings. Named EXEC argument labels are not caller variable uses. Duplicate/forward local names, dynamic and remote targets are explicit unsupported results.

`SqlNavigationIndex` consumes one completed immutable document snapshot set per request. Identities retain project context, server/database/schema/name and object kind. Identifier parts come from the AST, without splitting decoded names on dots. Resolution records status, candidates and provenance; a unique verified candidate is required for navigation. Reference search compares declaration anchors and resolves each supported static use, retaining the same source context. This initial in-memory implementation scans references rather than persisting a reverse cache; large-workspace benchmarks are later work.

`WorkspaceWatcher` coalesces native file events with a 100 ms debounce. SQL file events refresh individual snapshots; directory renames/deletes and watcher overflow reconcile the source registry. Non-SQL file writes do not trigger whole-workspace parsing. Native watcher setup failure preserves client notifications/re-open refresh and logs a status to stderr. Disk jobs have independent cancellation and identity guards, so an older read cannot overwrite a newer file result or an open buffer. Query requests wait for the current pending jobs and support cancellation.

`SqlLsp.Providers.SqlServer` supplies immutable catalog snapshots without LSP types. `SqlServerCatalogReader` accepts an approved profile, obtains its secret only in online mode, checks the configured endpoint/database, requires TLS, and runs fixed SELECT queries with typed filter/limit parameters. Reads discover visible objects, columns/types, parameters, allowed module source, dependencies, collation, user default schema and server version. Nullable source stays nullable. Catalog reads span an interval; they are not a transactionally consistent DDL snapshot.

`CatalogCache` serializes bounded acquisition, expires results by TTL, honors request cancellation and a total-load deadline, and retries one transient read failure. It never returns an expired snapshot after refresh fails. `CatalogDocuments` parses actual module text using its stored QUOTED_IDENTIFIER setting, writes process-owned private snapshots, and normalizes catalog identities into the same `IndexedSqlSymbol` model. The catalog object name remains authoritative even when stored SQL text predates sp_rename. Missing original source produces comments describing verified metadata, never fabricated CREATE statements.

`ServerState` selects one explicit profile context for online requests and combines opened analysis buffers with catalog documents through `SqlNavigationIndex`. Buffer declarations are not online global definitions unless repository scanning was explicitly requested. Ordinary file URIs work through the generic LSP client; snapshot edits received over text synchronization cannot replace catalog sources. Catalog dependencies retain their coverage/provenance in provider models but have no guaranteed source spans, so LSP references use only verified AST ranges. Status notifications distinguish ready, partial and unavailable metadata with snapshot timestamps.

Hybrid configuration maps initialized directory roots to explicitly enabled profiles. `SqlHybridPolicy` applies context/database/schema/kind filters, retains all matching source candidates, and chooses a navigation target only for one logical identity without duplicate declarations. Each database session owns its cache, private files and comparison rules. Acquisition is limited to two concurrent profiles with a shared 30-second refresh deadline. Failed sessions remove their catalog documents while retaining last verified identifier rules for local analysis; unrelated healthy profiles stay available. Unmapped roots retain their offline contexts.

`SqlDefinitionFingerprint` uses actual ScriptDOM declaration tokens, excludes comments/whitespace and acquisition headers, decodes identifier quoting, and preserves body values. Hash equality is normalized textual agreement, not semantic equivalence. `SqlDefinitionDriftAnalysis` emits Match/Different/Unavailable/Ambiguous only for mapped candidates; hidden, malformed and metadata-only sources remain unknown. Workspace symbol data contains provenance, comparison status and timestamps. Bounded status notifications summarize comparison without logging module text. Existing definition/references handlers use the same index; catalog and workspace anchors for one mapped identity share verified AST references. No edit/deployment capabilities are added.
